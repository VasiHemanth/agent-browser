Chrome extension + local hub

Chat with a coding agent that drives your real browser.

AgentBrowser is a Chrome side panel wired to a local hub. You talk to a coding harness; it clicks, types, reads and navigates in the browser you are already logged into. No automation profile, no re-login, no content scripts.

The problem it solves

Synthetic events from content scripts carry isTrusted: false, and modern editors built on Lexical or React composers ignore them outright. That is why so much browser automation silently fails to type into a real text box.

AgentBrowser dispatches input through chrome.debugger instead. CDP clicks and Input.insertText arrive exactly as a human's do. Because it attaches to your existing profile, the manifest asks for debugger, tabs, storage, offscreen, sidePanel and nothing else. No host permissions at all.

Architecture

Install

git clone https://github.com/VasiHemanth/agentbrowser.git
cd agentbrowser/server
npm install
npm start          # listens on ws://127.0.0.1:9010

Then open chrome://extensions, enable Developer mode, choose Load unpacked, and select the repo's extension/ directory. Click the toolbar icon; the status dot turns green when the hub is reachable.

Needs Chrome and Node.js 20.11 or newer.

Ten browser tools

toolargsresult
tabs_list{}every open tab with id, url, title, active
tab_new{url?}the new tabId
tab_close{tabId}confirmation
navigate{url, tabId?}url and title after load, 20s cap
read_page{tabId?, maxChars?}innerText, 60k char default cap
screenshot{tabId?}base64 PNG
click{x, y, tabId?}trusted CDP click
type_text{text, tabId?}inserts into the focused element
press_key{key, tabId?}e.g. Enter, Escape, Meta+A
eval_js{expression, tabId?}the evaluated value

Omit tabId to act on the active tab. The service worker attaches the debugger on demand, serializes commands per tab, and re-attaches if Chrome detaches it.

Bring your own backend

claude-agent-sdk

Runs in the hub process. Tools exposed as an in-process MCP server; screenshots come back as images the model can see.

claude-cli

Spawns claude -p in stream-json mode, kept alive for the session. Full Claude Code toolset alongside the browser tools.

codex · opencode · copilot

One process per turn, resumed through each CLI's own session mechanism. Browser tools attach over the stdio MCP proxy.

grok · agy · gemini

Same generic CLI wrapper, each with its own resume flag and MCP config shape.

anthropic-api · openai-api

Talk to the provider directly, no CLI needed. Keys live in ~/.agentchat/keys.json at mode 0600 and never reach the panel.

Anything that speaks MCP

mcp-proxy.mjs is a stdio MCP server forwarding to the hub. Point Cursor, Gemini CLI or another Claude Code at it.

Worth knowing before you install

  • Chrome allows one debugger client per tab. With DevTools open on a tab, tool calls on that tab fail until it detaches.
  • Chrome shows an "is being debugged" infobar while attached. Dismissing it detaches; the next tool call re-attaches.
  • The hub accepts one extension connection. A second profile displaces the first.
  • Filling a form is not permission to submit it. The harness will not click submit, send, post or buy unless you asked.
  • API keys are stored in plain text, protected by file permissions, not encrypted.
